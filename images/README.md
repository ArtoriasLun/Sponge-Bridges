# Where images and video go

The site is static, and a browser cannot list the contents of a directory. So
there is a manifest, `media.json` — generated by GitHub Actions. **You never
write it or think about it.**

The whole workflow is one sentence: **put the file in the right folder, push it,
and it shows up on the site.**

## `images/news/` — announcement header images

One image per announcement. **The filename must be the announcement's id:**

```
images/news/demo-v01.jpg     → appears on the "Demo v0.1 — Coming October 1" post
```

It shows up in two places at once: at the top of the article on the news page,
and in the "Latest News" card on the homepage. Leaving it out is fine — the post
simply has no header image.

Current announcement ids:

| id | Announcement |
|---|---|
| `demo-v01` | Sponge Bridges Demo v0.1 — Coming October 1! |

**Any aspect ratio works.** The page does not crop; the image keeps its own
proportions and fills the card's width. A Steam-shaped 1920×622 banner and an
ordinary 16:9 both show in full, so wordmarks never get cut off.

**One id, one file.** If both `demo-v01.jpg` and `demo-v01.webp` exist, only the
last one wins — delete the old file when you replace an image. The Actions log
prints a WARN if this ever happens.

## `images/gallery/` — screenshots and video

Anything in here joins the homepage carousel, **sorted by filename**, so prefix
them to control the order:

```
images/gallery/01-cargo-tower.jpg
images/gallery/02-red-mist.png
images/gallery/03-night-delivery.mp4
```

Images: `.jpg .jpeg .png .webp .avif .gif` — animated GIFs play.
Video: `.mp4 .webm` — muted, looping, inline, mixed in with the screenshots and
marked with a ▶ on its thumbnail.

### Captions (optional)

To caption a shot, add a line to `images/gallery/captions.json`. Files you skip
get no caption, and the file not existing at all is fine:

```json
{
  "01-cargo-tower.jpg": { "zh": "货塔越叠越高。", "en": "The stack grows." },
  "03-night-delivery.mp4": { "zh": "夜间送货。", "en": "A delivery after dark." }
}
```

## Two things to watch

**Keep video small.** Git is a poor home for large files, and GitHub rejects any
single file over 100MB outright. A short loop under 10MB is the right shape here;
put a full trailer on YouTube or Steam and link to it.

Prefer `.mp4` or `.webm` over `.gif`. A ten-second 720p clip is 20–50MB as a GIF
and 1–2MB as a video, and GIF is limited to 256 colours — which bands badly
across the red mist and firelight. The carousel already plays video muted and
looping, so it looks exactly like a GIF anyway.

**It only takes effect once pushed to GitHub.** Saving a file locally does
nothing: the manifest is rebuilt by Actions after the push. Give it a minute or
two and the page updates.
